# Lesson 001 — "Prisistatymo kortelė": design

Status: approved for planning
Date: 2026-10-03

## 1. Context and goal

First lesson of a Python course for Lithuanian 9th–11th graders. The group's
icebreaker *is* the first programming exercise: each pupil runs Python that
prints a personal ID card ("kortelė"), then reads it aloud so the group learns
each other's names.

The activity occupies 30–40 minutes inside a 3-hour class. Group size 10–20.
Skill levels range from "writes Python already" to "has never seen code".

## 2. Success criteria

1. Every pupil, including absolute beginners, prints a finished card.
2. No pupil is ever blocked by setup: no account, no install, no login.
3. The 3–4 pupils who already code are still working at minute 35.
4. The teacher circulates and talks to pupils instead of debugging the same
   `SyntaxError` fifteen times.
5. The engine is reusable by lessons 002+ without modification.

## 3. Constraints and settled decisions

| Decision | Rationale |
| --- | --- |
| JupyterLite (Pyodide), published to GitHub Pages | Python runs in the pupil's browser. No accounts, no server, no per-pupil kernel. Scales to 30 pupils at zero cost. |
| Stdlib only | Pyodide-safe, and keeps the engine runnable locally for later reuse. |
| Engine ships as a real bundled file `kortele.py` | JupyterLite bundles files into its virtual FS. The setup cell becomes one honest `import`, and Level 4 can send curious pupils to read the source. |
| Notebook generated by `build.py` from markdown + starter files | Lesson wording is edited as markdown, not as JSON inside an `.ipynb`. |
| All pupil-facing text in Lithuanian | Audience. Code keywords and identifiers stay ASCII. |
| Four tiers on one shared card | Beginners stop at tier 2 with a complete result; advanced pupils continue without a separate task. |
| `patikrink(n)` self-check per tier | Keeps 20 pupils unblocked without the teacher reaching each one. |

Explicitly rejected: Google Colab (requires Google accounts, and Workspace
admins can disable Colab as an additional service); self-hosted JupyterHub
(server-side kernels buy nothing here); ngrok tunnelling (bandwidth and
interstitial page against 20 devices); a single-file `.py` fallback (made
redundant by the offline USB copy of the static site).

## 4. Pupil experience

Five notebook sections. Each is a markdown cell followed by one code cell.

### Setup

```python
from kortele import rodyk_kortele, patikrink
```

### Level 1 — "Kas tu esi?"
Concepts: variable, string, integer, function call.

```python
vardas  = "Jonas"
amzius  = 16
miestas = "Vilnius"
faktas  = "moku groti gitara"

rodyk_kortele(vardas, amzius, miestas, faktas)
patikrink(1)
```

Ships pre-filled so running it works immediately — nobody faces a blank cell.
`patikrink(1)` detects the untouched placeholder and asks for their own data.

### Level 2 — "Ką mėgsti?"
Concepts: list, keyword argument.

```python
pomegiai = ["futbolas", "programavimas", "šunys"]

rodyk_kortele(vardas, amzius, miestas, faktas, pomegiai=pomegiai)
patikrink(2)
```

### Level 3 — "Slaptas programuotojo vardas"
Concepts: f-string, slicing, method call, arithmetic.

```python
slapyvardis = f"{vardas[:3].upper()}-{amzius * 2}"

rodyk_kortele(vardas, amzius, miestas, faktas, pomegiai=pomegiai, slapyvardis=slapyvardis)
patikrink(3)
```

Two lines, four new concepts, and an output pupils want to compare with their
neighbour.

### Level 4 — "Laisvas režimas"
Open brief, no template. Three suggested directions:

- **a)** Write `slapyvardis_is(vardas, amzius)` as a reusable function.
  `patikrink(4)` calls it with its own inputs and reports what it found.
- **b)** Random fact per run via `random.choice`.
- **c)** `rodyk_kortele` accepts an undocumented `tema=` argument. Which themes
  exist? The answer is in `kortele.py`, open from the file browser.

`patikrink(4)` never reports failure — it reports what it detected and
encourages. Level 4 has no single correct answer.

### Timing

| Minutes | Activity |
| --- | --- |
| 3 | Teacher frames the activity |
| 5 | Everyone opens the URL, runs the setup cell |
| 8 | Level 1 |
| 7 | Level 2 |
| 7 | Level 3 |
| remainder | Level 4 |
| final 8 | Each pupil reads their card aloud |

## 5. Engine API (`kortele.py`)

Two public functions; everything else is module-private.

```python
def rodyk_kortele(vardas, amzius, miestas, faktas, *,
                  pomegiai=None, slapyvardis=None, tema="klasika") -> None
def patikrink(lygis, *, erdve=None) -> None
```

**`rodyk_kortele`** renders and prints the card. Optional fields are omitted
from the card when `None`, so the same call signature grows across levels.
Themes differ by border characters and accent emoji; at least `"klasika"`,
`"matrix"`, `"neonas"` exist. Invalid input never raises: a wrong type or an
unknown theme prints a Lithuanian sentence explaining the fix.

Each call records its arguments in a module-private `_paskutine_kortele`. This
is how `patikrink` distinguishes "variable was defined" from "variable was
passed to the card" — that distinction is most of the pedagogical point of
levels 2 and 3.

**`patikrink`** defaults `erdve` to the caller's globals, so pupils write a bare
`patikrink(2)` while tests inject a dict. Every check produces one of three
Lithuanian outcomes, never a traceback:

- ✅ pass,
- ✋ placeholder still untouched,
- a specific hint naming the variable at fault.

Per-level checks:

| Level | Passes when |
| --- | --- |
| 1 | `vardas`, `miestas`, `faktas` are non-empty strings; `amzius` is an int; none still hold placeholder values; the card was rendered |
| 2 | `pomegiai` is a list of ≥2 non-empty strings *and* was passed to `rodyk_kortele` |
| 3 | `slapyvardis` is a non-empty string, differs from `vardas`, and was passed to `rodyk_kortele` |
| 4 | Always reports; describes which of (a)/(b)/(c) it detected. If `slapyvardis_is` exists, it is called with the engine's own inputs and its return value is checked for being a non-constant string |

### Card width handling

Alignment is computed with a private display-width helper: combining marks and
variation selectors count 0, East Asian Wide/Fullwidth and emoji count 2,
everything else counts 1. Lithuanian diacritics are single-width code points
and align exactly.

**Known limitation:** emoji width in a browser monospace font is font-dependent,
so an emoji inside the card interior may drift by one column. Accepted. Tests
assert exact alignment for ASCII and Lithuanian text, and only non-crashing
best-effort alignment for emoji. Themes keep emoji in positions where a
one-column drift is not visible.

## 6. Repository layout

```
001/
  README.md                     # what this lesson is, how to build it
  mokytojui.md                  # teacher guide
  kortele.py                    # the engine — the only non-trivial code
  turinys/
    00_ivadas.md   00_ivadas.py
    01_lygis.md    01_lygis.py
    02_lygis.md    02_lygis.py
    03_lygis.md    03_lygis.py
    04_lygis.md    04_lygis.py
  sprendimai.py                 # reference solutions, one per level
  build.py
  tests/
    test_rodyk_kortele.py
    test_patikrink.py
    test_build.py
  requirements-dev.txt          # jupyterlite-core, jupyterlite-pyodide-kernel, pytest
  .github/workflows/deploy.yml
  dist/                         # generated site, gitignored
```

Each level is a `.md` (rendered as a markdown cell) paired with a `.py`
(the starter code cell). Adding a level means adding a pair.

## 7. Build and deploy

`build.py` runs three steps:

1. Pair each `turinys/NN_*.md` with its `.py` into markdown+code cell pairs,
   in filename order.
2. Write `intro_kortele.ipynb`.
3. Invoke `jupyter lite build`, bundling `intro_kortele.ipynb` and `kortele.py`
   as notebook contents, output to `dist/`.

Deployment is a GitHub Action on push to `main`: install dev requirements, run
`pytest`, run `build.py`, publish `dist/` to GitHub Pages. The URL is stable
across lessons, so the link given to pupils never changes.

Offline fallback: copy `dist/` to a USB stick and serve it with
`python -m http.server` from the teacher's laptop. Same artifact, no internet.

## 8. Testing strategy

Test-first on the engine; the engine is the part that must not fail in front of
20 teenagers.

**`test_rodyk_kortele.py`**
- Card borders stay aligned across Lithuanian diacritics, absent optional
  fields, and very long input (which is truncated, not allowed to break the box).
- Every theme renders.
- Wrong types and unknown themes print a Lithuanian message and do not raise.
- `_paskutine_kortele` records exactly the arguments passed.

**`test_patikrink.py`**
- Each level × {pass, placeholder untouched, wrong type, defined-but-not-passed}.
- `erdve` injection works, so no test depends on real globals.
- Level 4 never reports failure for any input.

**`test_build.py`**
- The generated notebook is valid JSON with the expected cell sequence.
- Every starter snippet in `turinys/*.py` `compile()`s — a notebook that greets
  pupils with a `SyntaxError` is the worst possible opening.
- **Load-bearing:** every solution in `sprendimai.py` is executed and run
  through `patikrink` for its level, and must pass. A change to a check that
  breaks the reference answer fails CI rather than the classroom.

Not covered by automated tests: JupyterLite itself, Pyodide, and the Pages
deploy. These get the teacher guide's manual pre-lesson checklist instead.

## 9. Teacher guide (`mokytojui.md`)

- The Pages URL, and the USB fallback procedure.
- **Pre-lesson checklist**, run on the school network, not at home: open the
  Pages URL on a phone over school wifi; confirm Pyodide finishes loading;
  confirm the school content filter does not block `github.io`.
- Minute-by-minute timing (section 4).
- Reference solutions for all four levels.
- The four errors that will actually occur, each with the Lithuanian one-liner
  that fixes it: missing quotes around text; smart quotes pasted from a chat
  app; Lithuanian letters used in a variable name; missing comma in a list.
- Prompts for the card-sharing round.

## 10. Risks

| Risk | Mitigation |
| --- | --- |
| School content filter blocks `*.github.io` | Pre-lesson check from the school network; USB copy of `dist/` |
| 20 devices each pulling ~15–20 MB of Pyodide at once | Warn pupils not to refresh; stagger by starting the setup cell in two waves; LAN copy if wifi is weak |
| Low-RAM Chromebooks struggle with Pyodide | Verify on one school device before the lesson; pair pupils if needed |
| JupyterLite stores work in browser storage — cleared data loses it | Lesson is self-contained in 40 minutes; teacher guide mentions "Download" for anyone who wants to keep their card |
| Pupils without a device | Pair them; the activity works fine with two per screen |

## 11. Out of scope

- Collecting cards into a shared class gallery (no backend by design).
- A guess-who quiz built on the collected data.
- Turtle or other graphical output.
- Persisting pupil work between lessons.
- Lessons 002+ content, though the engine is designed to be imported by them.

## 12. Open questions for the teacher
