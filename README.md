# Lesson 001 — "Prisistatymo kortelė" + "Flagų misija"

A ~70-minute introductory Python lesson for Lithuanian 9th-11th graders,
delivered as a JupyterLite notebook (Pyodide, runs entirely in the browser,
nothing to install on pupil devices).

**Challenge 1 — Kortelė:** pupils fill in variables and render a personal
"ID card" through four levels of increasing difficulty (basic fields →
hobbies list → derived nickname → free-form extension).

**Challenge 2 — Flagų misija:** pupils are sent to named classmates, must
find a shared interest, and exchange derived "flags"; collected interests
land back on the card, which pupils read aloud at the end. The lesson
closes with a five-minute security debrief: the flag-checking mechanism
doubles as a lesson in why client-side secrets aren't secrets.

The teacher-facing guide, in Lithuanian, is [`mokytojui.md`](mokytojui.md) —
read that for lesson delivery (timing, common mistakes, the pairing tool,
the scripted debrief). This file is for anyone building, testing, or
maintaining the lesson content itself.

## Quick start

All commands assume the project venv at `.venv/`; invoke Python via
`./.venv/bin/python` so the correct interpreter and installed packages are
used regardless of whether the venv is activated.

```bash
# install dev/build dependencies (jupyterlite-core, jupyterlite-pyodide-kernel,
# jupyter-server, pytest)
./.venv/bin/python -m pip install -r requirements-dev.txt

# run the test suite
./.venv/bin/python -m pytest -q

# build intro_kortele.ipynb only (fast, no JupyterLite build)
./.venv/bin/python build.py --tik-nb

# build the notebook AND the full JupyterLite site into dist/
./.venv/bin/python build.py

# generate the pairing table + per-pupil flags for a class list
./.venv/bin/python poros.py klase.txt --kodas ZEBRAI2026 --raundai 3
```

`poros.py` prints a projectable round-robin pairing table and the teacher's
reference list of every pupil's flag to the terminal, and writes a
standalone `poros_lentele.html` for projecting. Every foreseeable roster
problem is checked *before* the first line is printed — missing file, fewer
than two names, more rounds than pairings allow, names that collide after
normalisation (same flag would result), and names no flag can be derived
from — each refusing with a Lithuanian message and exit code 1 rather than
a traceback over a half-printed table.

## File map

**Engines** (imported by the notebook and by `tests/`; no side effects on
import):
- `kortele.py` — Challenge 1. `rodyk_kortele(...)` renders the card;
  `patikrink(lygis)` acknowledges a level; it verifies nothing (one of four
  levels. Never raises; every bad input path prints a Lithuanian message.
- `misija.py` — Challenge 2. `pradek_misija(vardas, klases_kodas, *,
  klases_kodas)` registers a pupil and shows their flag; `irasyk_flaga(vardas,
  flagas, bendras_interesas)` verifies a partner's flag and records the
  shared interest; `misijos_bukle()` prints progress. Flags are derived via
  HMAC from the pupil's name and the class code — nothing is persisted or
  looked up from a roster.

**Lesson content:**
- `turinys/NN_*.md` + `turinys/NN_*.py` — one markdown + starter-code cell
  pair per notebook section, assembled in filename order by `build.py`.
  Adding a section means adding a pair.
- `sprendimai.py` — reference solutions, `sprendimas_1()`..`sprendimas_4()`.
  These chain (`sprendimas_2` calls `sprendimas_1` and extends its result,
  and so on), so concrete starter values live only in `sprendimas_1`; read
  the file top-to-bottom, not as four independent functions.
- `intro_kortele.ipynb` — generated by `build.py`; do not hand-edit, it
  will be overwritten.

**Teacher tooling (never bundled into the deployed site):**
- `poros.py` — builds the pairing table and per-pupil flag list from a
  class roster.
- `klase.txt` — the class roster, one name per line. **Gitignored, never
  committed** — it's a list of real pupils' names.
- `poros_*.html` — generated projectable pairing table. **Gitignored,
  never committed** — same reason, and it also contains flags.

**Build and deploy:**
- `build.py` — assembles `turinys/` into `intro_kortele.ipynb`, then (unless
  `--tik-nb`) runs `jupyter lite build` to produce the static site in
  `dist/`, bundling the notebook plus `kortele.py` and `misija.py` as
  notebook contents.
- `requirements-dev.txt` — pinned build/test dependencies.
- `.github/workflows/deploy.yml` — on push to `main`: installs
  dependencies, runs the test suite, runs `build.py`, publishes `dist/` to
  GitHub Pages via `actions/deploy-pages`.
- `dist/` — generated site. Gitignored, never committed; rebuilt by CI on
  every push and locally via `build.py`.

**Tests** (`tests/`, run with `./.venv/bin/python -m pytest`):
- `test_rodyk_kortele.py`, `test_misija.py` — engine
  behaviour, including that malformed input never raises.
- `test_poros.py` — pairing correctness, the name-collision guard, and
  every refusal path in `main()`.
- `test_build.py` — the generated notebook is valid, every starter snippet
  compiles, every `@@token@@` resolves to its engine value, and the committed
  `intro_kortele.ipynb` matches what `build.py` would generate right now.
- `test_sprendimai.py` — the reference solutions: each `sprendimas_N()` is
  executed and the namespace it returns is checked against `patikrink(N,
  ...)`, so a broken reference solution fails CI rather than the classroom.

## Never commit

`klase.txt` and `poros_*.html` contain real pupils' names (and, for the
HTML file, their derived flags). Both are listed in `.gitignore`. Do not
force-add them, and double-check `git status` before committing if you've
been testing `poros.py` locally.
