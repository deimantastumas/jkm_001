# Lesson 001 — "Prisistatymo kortelė" + "Flagų misija": design

Status: approved for planning
Date: 2026-10-03

## 1. Context and goal

First lesson of a Python course for Lithuanian 9th–11th graders. The group's
icebreaker *is* the first programming exercise, in two linked challenges:

1. **Kortelė** — each pupil runs Python that prints a personal ID card.
2. **Flagų misija** — pupils are sent to named classmates, must find a shared
   interest, and exchange flags that only the other person's screen can show
   them. The collected interests land back on the card.

Together they occupy ~70 minutes inside a 3-hour class. Group size 10–20.
Skill levels range from "writes Python already" to "has never seen code".

## 2. Success criteria

1. Every pupil, including absolute beginners, prints a finished card.
2. No pupil is ever blocked by setup: no account, no install, no login.
3. Challenge 2 cannot be completed alone — progress requires conversations.
4. The 3–4 pupils who already code are still working at the end.
5. The teacher circulates and talks to pupils instead of debugging the same
   `SyntaxError` fifteen times.
6. No pupil's personal data is published anywhere.
7. The engine is reusable by lessons 002+ without modification.

## 3. Constraints and settled decisions

| Decision | Rationale |
| --- | --- |
| JupyterLite (Pyodide), published to GitHub Pages | Python runs in the pupil's browser. No accounts, no server, no per-pupil kernel. Scales to 30 pupils at zero cost. |
| Stdlib only | Pyodide-safe, and keeps the engine runnable locally for later reuse. |
| Engine ships as real bundled files `kortele.py`, `misija.py` | JupyterLite bundles files into its virtual FS. Setup cells become honest `import`s, and Level 4 can send curious pupils to read the source. |
| Notebook generated by `build.py` from markdown + starter files | Lesson wording is edited as markdown, not as JSON inside an `.ipynb`. |
| All pupil-facing text in Lithuanian | Audience. Code keywords and identifiers stay ASCII. |
| Flags **derived**, never stored; no class roster in the deployed site | Names of minors must not appear on a public URL. Also removes any per-class rebuild: one generic deploy serves every class. |
| Pairings projected by the teacher, not served by the site | Same reason. The site never needs to know who is in the room. |
| Mutual pairing (A↔B in rounds) | One-directional assignment produces twenty pupils wandering into each other's half-finished conversations. |
| Client-side flag derivation is *accepted*, not mitigated | Impossible to prevent without a server, and it is the lesson's best teaching moment (§4.3). |
| `patikrink(n)` self-check per tier | Keeps 20 pupils unblocked without the teacher reaching each one. |

Explicitly rejected: Google Colab (requires Google accounts, and Workspace
admins can disable Colab as an additional service); self-hosted JupyterHub
(server-side kernels buy nothing here); ngrok tunnelling (bandwidth and
interstitial page against 20 devices); a single-file `.py` fallback (made
redundant by the offline USB copy of the static site); storing a class roster
or flag table in the repo (PII, and forces a rebuild per class).

## 4. Pupil experience

Each notebook section is a markdown cell followed by one code cell.

### 4.1 Challenge 1 — Kortelė

**Setup**

```python
from kortele import rodyk_kortele, patikrink
```

**Level 1 — "Kas tu esi?"** · variable, string, integer, function call

```python
vardas  = "Jonas"
amzius  = 16
miestas = "Vilnius"
faktas  = "moku groti gitara"

rodyk_kortele(vardas, amzius, miestas, faktas)
patikrink(1)
```

Ships pre-filled so running it works immediately — nobody faces a blank cell.
`patikrink(1)` detects the untouched placeholder and asks for their own data.

**Level 2 — "Ką mėgsti?"** · list, keyword argument

```python
pomegiai = ["futbolas", "programavimas", "šunys"]

rodyk_kortele(vardas, amzius, miestas, faktas, pomegiai=pomegiai)
patikrink(2)
```

**Level 3 — "Slaptas programuotojo vardas"** · f-string, slicing, method call,
arithmetic

```python
slapyvardis = f"{vardas[:3].upper()}-{amzius * 2}"

rodyk_kortele(vardas, amzius, miestas, faktas, pomegiai=pomegiai, slapyvardis=slapyvardis)
patikrink(3)
```

Two lines, four new concepts, and an output pupils want to compare with their
neighbour.

**Level 4 — "Laisvas režimas"** · open brief, no template

- **a)** Write `slapyvardis_is(vardas, amzius)` as a reusable function.
  `patikrink(4)` calls it with its own inputs and reports what it found.
- **b)** Random fact per run via `random.choice`.
- **c)** `rodyk_kortele` accepts an undocumented `tema=` argument. Which themes
  exist? The answer is in `kortele.py`, open from the file browser.

`patikrink(4)` never reports failure — it reports what it detected and
encourages. Level 4 has no single correct answer.

### 4.2 Challenge 2 — Flagų misija

**Setup**

```python
from misija import pradek_misija, irasyk_flaga, misijos_bukle

pradek_misija("Birutė", "ZEBRAI2026")
```

Prints the pupil's own flag and the rules. The class code comes off the
whiteboard.

**Main cell** — re-run once per conversation:

```python
irasyk_flaga("Tomas", "TOMA-4417", "krepšinis")
misijos_bukle()
```

**Bonus cell** for fast finishers — dictionary, tuple unpacking, `for` loop:

```python
draugai = {
    "Tomas": ("TOMA-4417", "krepšinis"),
    "Eglė":  ("EGLE-9930", "šunys"),
}
for vardas, (flagas, interesas) in draugai.items():
    irasyk_flaga(vardas, flagas, interesas)
```

**Final cell** — re-render the card, which has now grown a section:

```
Bendri interesai:  su Tomu – krepšinis
                   su Egle – šunys
                   su Kaziu – Minecraft
```

This is what pupils read aloud. The shared-interest field cannot be verified by
code and is not meant to be — reading the card to the group is the
accountability.

### 4.3 The security debrief

Closing five minutes, scripted in `mokytojui.md`:

> *"Ar kas nors gavo flagą nepakalbėjęs su tuo žmogumi?"*

Whoever did gets credit, then the teacher explains what they proved: the page
verifies flags, therefore the page can generate flags, therefore nothing the
browser receives is secret. This is the intended ending, not a leak to be
patched.

### 4.4 Timing

| Minutes | Activity |
| --- | --- |
| 3 | Teacher frames the activity |
| 5 | Everyone opens the URL, runs the setup cell |
| 8 | Level 1 |
| 7 | Level 2 |
| 7 | Level 3 |
| ~8 | Level 4 (fast finishers; others catch up) |
| 2 | Mission framing, pairing table projected, class code on the board |
| 2 | Everyone runs `pradek_misija`, sees their flag |
| 15 | 3 rounds × 5 min, teacher calls "keičiamės" on a timer |
| 4 | Final card render |
| 5 | Security debrief |

Round length is the number most likely to need adjusting on the day; the guide
says so explicitly.

## 5. Engine API

### 5.1 `kortele.py`

```python
def rodyk_kortele(vardas, amzius, miestas, faktas, *,
                  pomegiai=None, slapyvardis=None, tema="klasika",
                  bendri_interesai=None) -> None
def patikrink(lygis, *, erdve=None) -> None
```

`rodyk_kortele` renders and prints the card. Optional fields are omitted when
`None`, so the same call signature grows across levels. Themes differ by border
characters and accent emoji; at least `"klasika"`, `"matrix"`, `"neonas"`
exist. Invalid input never raises: a wrong type or an unknown theme prints a
Lithuanian sentence explaining the fix. Long field values are truncated to the
card width rather than breaking the box.

`bendri_interesai=None` falls back to the live mission state via a **lazy**
`import misija` inside the function body. The dependency is one-directional
(`kortele` → `misija`) and exists only so the final render needs no extra
argument from the pupil; passing the value explicitly bypasses it entirely,
which is how tests exercise the card.

Each call records its arguments in a module-private `_paskutine_kortele`. This
is how `patikrink` distinguishes "variable was defined" from "variable was
passed to the card" — that distinction is most of the pedagogical point of
levels 2 and 3.

`patikrink` defaults `erdve` to the caller's globals, so pupils write a bare
`patikrink(2)` while tests inject a dict. Every check produces one of three
Lithuanian outcomes, never a traceback: ✅ pass, ✋ placeholder still untouched,
or a specific hint naming the variable at fault.

| Level | Passes when |
| --- | --- |
| 1 | `vardas`, `miestas`, `faktas` are non-empty strings; `amzius` is an int; none still hold placeholder values; the card was rendered |
| 2 | `pomegiai` is a list of ≥2 non-empty strings *and* was passed to `rodyk_kortele` |
| 3 | `slapyvardis` is a non-empty string, differs from `vardas`, and was passed to `rodyk_kortele` |
| 4 | Always reports; describes which of (a)/(b)/(c) it detected. If `slapyvardis_is` exists, it is called with the engine's own inputs and its return value is checked for being a non-constant string |

Placeholder detection: `kortele.py` owns the canonical placeholder values
(`"Jonas"`, `16`, `"Vilnius"`, `"moku groti gitara"`, and the starter
`pomegiai` list) in a module-private constant, and `turinys/*.py` is generated
from it at build time. The starter cells and the checks cannot drift apart.

### 5.2 `misija.py`

```python
def normalizuok(vardas) -> str
def generuok_flaga(vardas, klases_kodas) -> str
def pradek_misija(vardas, klases_kodas, *, tikslas=3) -> None
def irasyk_flaga(vardas, flagas, bendras_interesas) -> None
def misijos_bukle() -> None
def surinkti() -> list[tuple[str, str]]     # [(display name, shared interest)]
```

**Flag format** — `LETTERS-DDDD`:

- letter block: `normalizuok(vardas)`, uppercased, `A–Z` only, first 4
  characters; 2–4 characters long. Fewer than 2 usable letters is a
  Lithuanian error message, not an exception.
- digit block: `HMAC-SHA256(key=klases_kodas, msg=normalizuok(vardas))`, first
  4 bytes as an integer, `% 10000`, zero-padded to 4.

Letters and digits are positionally separated by the hyphen, so no glyph is
ambiguous about which block it belongs to. Ambiguous *glyphs* (`O` vs `0`)
cannot be avoided — the letter block comes from the pupil's own name.

**`normalizuok`** — casefold, strip, collapse internal whitespace, NFD-decompose
and drop combining marks, so `Birutė`, `Birute`, `birutė ` and `BIRUTĖ` all
produce the same flag. This is the single most likely field failure and is the
first test written.

**`irasyk_flaga`** recomputes the partner's flag from the name and the class
code stored by `pradek_misija`, and compares. It rejects: the pupil's own name,
a name already recorded, and a mismatched flag — each with a Lithuanian hint
naming what to check, never a traceback. It never consults a roster, so a pupil
whose assigned partner is absent or busy can simply go to someone else; the
`tikslas=3` target is a count, not a list.

`misijos_bukle()` prints progress (`2/3 — dar vienas pokalbis!`) and the names
already recorded.

### 5.3 Card width handling

Alignment is computed with a private display-width helper: combining marks and
variation selectors count 0, East Asian Wide/Fullwidth and emoji count 2,
everything else counts 1. Lithuanian diacritics are single-width code points
and align exactly.

**Known limitation:** emoji width in a browser monospace font is font-dependent,
so an emoji inside the card interior may drift by one column. Accepted. Tests
assert exact alignment for ASCII and Lithuanian text, and only non-crashing
best-effort alignment for emoji. Themes keep emoji in positions where a
one-column drift is not visible.

and `misija.py` are.

## 7. Teacher tooling — `poros.py`

Run locally before the lesson:

```
python poros.py klase.txt --kodas ZEBRAI2026 --raundai 3
```

Outputs:

1. A **mutual round-robin table** for 3 rounds, suitable for projecting. Odd
   headcount produces one trio per round rather than leaving a pupil idle.
2. The teacher's **reference list of every pupil's flag**, so a stuck pupil can
   be unstuck in seconds.
3. A **duplicate-name warning**: two pupils whose normalised names collide get
   the same flag. The fix is to register one as `"Lukas B."`; this must be
   caught before the lesson, which is why the script refuses to print a table
   until collisions are resolved.

Output goes to the terminal and to a standalone HTML file for projecting.
Neither is committed.

## 8. Build and deploy

`build.py`:

1. Pair each `turinys/NN_*.md` with its `.py` into markdown+code cell pairs, in
   filename order, substituting the placeholder values exported by `kortele.py`
   into the starter snippets.
2. Write `intro_kortele.ipynb`.
3. Invoke `jupyter lite build`, bundling the notebook, `kortele.py` and
   `misija.py` as notebook contents, output to `dist/`.

Deployment is a GitHub Action on push to `main`: install dev requirements, run
`pytest`, run `build.py`, publish `dist/` to GitHub Pages. The URL is stable
across lessons and classes, so the link never changes.

Offline fallback: copy `dist/` to a USB stick and serve it with
`python -m http.server` from the teacher's laptop. Same artifact, no internet.

## 9. Testing strategy

Test-first on both engines; they are the part that must not fail in front of 20
teenagers.

**`test_misija.py`** — written first.
- `normalizuok` folds every Lithuanian diacritic (`ąčęėįšųūž`), case, and
  surrounding/internal whitespace to one canonical form.
- `generuok_flaga` is stable across all those spellings and differs between
  names, and between class codes for the same name.
- Flag format: letter block 2–4 `A–Z`, hyphen, exactly 4 digits.
- Names with too few usable letters produce a message, not an exception.
- `irasyk_flaga` rejects own name, duplicate name, and wrong flag, each with a
  distinct message, and raises nothing.
- `surinkti()` preserves insertion order and the pupil's original spelling of
  the partner's name for display.

**`test_rodyk_kortele.py`**
- Card borders stay aligned across Lithuanian diacritics, absent optional
  fields, and very long input (truncated, not allowed to break the box).
- Every theme renders.
- Wrong types and unknown themes print a Lithuanian message and do not raise.
- `_paskutine_kortele` records exactly the arguments passed.
- `bendri_interesai` renders when passed explicitly, and the lazy mission
  fallback is exercised separately.

**`test_patikrink.py`**
- Each level × {pass, placeholder untouched, wrong type, defined-but-not-passed}.
- `erdve` injection works, so no test depends on real globals.
- Level 4 never reports failure for any input.

**`test_poros.py`**
- Pairings are mutual in every round, nobody is paired with themselves, and no
  pair repeats across rounds.
- Odd headcount produces exactly one trio per round and leaves nobody idle.
- Colliding names block table output.

**`test_build.py`**
- The generated notebook is valid JSON with the expected cell sequence.
- Every starter snippet in `turinys/*.py` `compile()`s — a notebook that greets
  pupils with a `SyntaxError` is the worst possible opening.
- **Load-bearing:** each `sprendimas_N()` is executed and the namespace it
  returns is passed to `patikrink(N, erdve=...)`, which must pass. A change to a
  check that breaks the reference answer fails CI rather than the classroom.

Not covered by automated tests: JupyterLite itself, Pyodide, and the Pages
deploy. These get the teacher guide's manual pre-lesson checklist instead.

## 10. Teacher guide (`mokytojui.md`)

- The Pages URL, and the USB fallback procedure.
- **Pre-lesson checklist**, run on the school network, not at home: open the
  Pages URL on a phone over school wifi; confirm Pyodide finishes loading;
  confirm the school content filter does not block `github.io`; run `poros.py`
  and resolve any name collisions.
- Minute-by-minute timing (§4.4), flagging round length as the dial to turn.
- Reference solutions for all four levels.
- The four errors that will actually occur, each with the Lithuanian one-liner
  that fixes it: missing quotes around text; smart quotes pasted from a chat
  app; Lithuanian letters used in a variable name; missing comma in a list.
- Mission logistics: class code on the board, pairing table projected, a timer,
  and the "keičiamės" call.
- A **scripted security debrief** (§4.3) — written out so it can be read, and
  improvised over if preferred.
- Prompts for the card-sharing round.

## 11. Risks

| Risk | Mitigation |
| --- | --- |
| School content filter blocks `*.github.io` | Pre-lesson check from the school network; USB copy of `dist/` |
| 20 devices each pulling ~15–20 MB of Pyodide at once | Warn pupils not to refresh; start the setup cell in two waves; LAN copy if wifi is weak |
| Low-RAM Chromebooks struggle with Pyodide | Verify on one school device before the lesson; pair pupils if needed |
| JupyterLite stores work in browser storage — cleared data loses it | Lesson is self-contained; guide mentions "Download" for anyone who wants to keep their card |
| Pupils without a device | Pair them; both challenges work with two per screen |
| Duplicate first names collide to one flag | `poros.py` refuses to emit a table until resolved |
| 18 teenagers moving on a timer is loud and some drift | Timed rounds, projected table; two concentric circles with the outer one rotating if the room is small |
| A pupil finishes challenge 1 late and misses round 1 | `irasyk_flaga` accepts any classmate, so they catch up with whoever is free |

## 12. Out of scope

- Any server-side component, and therefore any genuinely secret flag.
- Collecting cards into a shared class gallery.
- Turtle or other graphical output.
- Persisting pupil work between lessons.
- Lessons 002+ content, though both engines are designed to be imported by them.
